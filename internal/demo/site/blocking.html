A page that blocks when you interact

The click handler occupies the main thread before it responds.

What this page does Each button runs a synchronous loop before updating the page, so the browser cannot paint the response until it finishes. That delay is what INP measures. Note that this tool approximates INP as the longest single event, not the high percentile that real INP reports.

Click both, in any order. The second one is considerably worse.

Real pages do this accidentally: a click handler that reflows a large table, parses a big JSON payload, or re-renders a whole component tree synchronously. The fix is to yield to the browser before doing the work, so the interaction can paint first.

Every page here loads /b.js, the 942-byte beacon, from this same server. Measurements are sent once, when you leave the page or switch tabs, so click through a few pages and then open the dashboard.
